# Battle UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Играбельный интерфейс «Затмения» в мобильном браузере поверх готового движка: бой против бота с проигрыванием раунда, обучение из трёх сценарных боёв, конструктор колод с архетипами, героини, сохранение прогресса.

**Architecture:** Движок `src/engine` остаётся источником истины; слой `src/game` оборачивает его в сессию матча, проигрывание событий, сценарии обучения, пресеты и сохранение, всё без React. Один Zustand-store с срезами хранит профиль, колоды, настройки и текущий матч; экраны на React читают селекторы и зовут действия store. Проигрывание строится из событий раунда: чистый редуктор отображения применяет события по одному, Framer Motion анимирует биты.

**Tech Stack:** React 18, TypeScript 5, Vite 5, Zustand 4, Framer Motion 11, CSS-модули, Vitest 2 + @testing-library/react + jsdom, Playwright 1.4x для одного сквозного теста.

**Spec:** `docs/specs/2026-10-28-battle-ui-design.md` (движок: `docs/specs/2026-10-27-battle-engine-design.md`, §10 там обязателен)

## Global Constraints

- `src/engine/**` не импортирует ничего извне `src/engine`; `src/game/**` не импортирует React и DOM; `src/screens` и `src/ui` зовут движок только через `src/engine/index.ts` и `src/game/*`.
- Все строки интерфейса в `src/i18n/ru.ts`; в компонентах нет русских литералов.
- Цвета и размеры только через переменные из `src/styles/tokens.css`: `--bg #0b0e1f`, `--surface #161a33`, `--text #e8e6ff`, `--muted #8f8fb3`, `--accent #f2c76b`, `--danger #ff5c7a`; стихии fire `#ff7a45`, water `#4cc3ff`, wind `#7ee787`, light `#ffe08a`, dark `#b48cff`, star `#ff9ad5`; минимальная цель тапа 44px.
- Ключ сохранения `eclipse.save`, схема `SaveV1` из спеки §8.
- Длительности битов из спеки §4.2 как именованные константы в `src/game/playback/timings.ts`.
- Тесты: описания на русском, код на английском; компоненты тестируются с реальным store и реальным движком, без моков движка.
- Коммит после каждой задачи: `feat(ui): …`, `feat(game): …`, `feat(engine): …`, `test: …`.
- Задачи 1–2 меняют `src/engine` и выполняются только после слияния ветки балансового прохода в `main`. Задачи 3, 4 и 8 не зависят от них и могут идти раньше; задачи 5–7 используют `ValidationIssue`, `legalActions` и `EngineEvent`, поэтому идут после задач 1–2.

## Review Focus

1. Матч восстановлен из localStorage посреди проигрывания (вкладка закрыта во время анимации): ожидается планирование того же раунда, никаких повторных вызовов `resolveRound` (тест в Task 5).
2. Героиня игрока погибла в проигрывании, а черновик следующего раунда ещё содержит её действие: черновик сбрасывается, «Подтвердить» не считает мёртвую (тест в Task 6).
3. Тап по цели, ставшей нелегальной после смены действия (выбрали «Ульту» вместо «Скилла» с другим типом цели): подсветка пересчитывается, старый чип снимается (тест в Task 9).
4. «Собрать за меня» при ровно 4 открытых героинях: ролей не хватает, колода всё равно легальна (тест в Task 12).
5. Обучение: игрок открывает лист действий у не той героини: лист не открывается, подсказка остаётся (тест в Task 15).
