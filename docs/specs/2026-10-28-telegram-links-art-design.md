# «Затмение» — спека выкладки, Telegram Mini App, ссылок-вызовов и арта (подпроект 3 из 3)

Дата: 2026-10-28. Статус: на ревью. Предшественники: спека движка `docs/specs/2026-10-27-battle-engine-design.md`, спека интерфейса `docs/specs/2026-10-28-battle-ui-design.md` (обе реализованы, слиты в `main`).

Подпроект 3 выводит игру к людям: публичный адрес, запуск внутри Telegram тем же кодом, вызов друга ссылкой без сервера, кнопка «Поделиться», портреты героинь.

## 1. Цель и критерии готовности

Цель: игрок открывает игру по ссылке в браузере или в Telegram, играет, отправляет другу вызов, друг открывает ссылку и сразу играет против его команды.

Готово, когда:

1. `https://alessioilini.github.io/eclipse/` открывает игру; деплой происходит автоматически из `main` после зелёных тестов.
2. Тот же адрес открывается как Telegram Mini App: игра занимает весь экран, кнопка «Назад» Telegram работает как внутренняя, прогресс хранится в облаке Telegram и восстанавливается на другом устройстве.
3. Ссылка-вызов длиной не более 100 символов открывает экран вызова с именем отправителя и его составом; «Принять вызов» запускает бой против призрака с колодой и seed отправителя; у всех получателей одинаковый противник.
4. «Поделиться» на экране результата даёт текст с ключевым моментом и ссылкой; в Telegram открывается окно пересылки, в браузере системный шаринг или копирование.
5. У всех 12 героинь есть портрет и арт в рост, они показываются в бою, в сетке, в карточке героини, в конструкторе и на экране вызова; при отсутствии файла остаётся инициал.
6. Lighthouse Performance главного меню не ниже 80 на профиле из спеки интерфейса §13; арт не входит в стартовый бандл.
7. Сквозной тест Playwright: открыть ссылку-вызов, принять, увидеть в бою состав призрака.

Вне рамок: сервер, рейтинг, автоматические ответные вызовы, платежи, арт карт, звук, PWA-установка, Telegram Stars.

## 2. Деплой

- Vite собирает с базовым путём из переменной окружения: `base: process.env.BASE_PATH ?? '/'`. Workflow задаёт `BASE_PATH=/eclipse/`; локально и в Playwright база `/`.
- `.github/workflows/deploy.yml`: на push в `main`: Node 20, `npm ci`, `npm test`, `npm run build`, публикация `dist` через `actions/upload-pages-artifact` и `actions/deploy-pages`. Любой красный шаг отменяет публикацию.
- Хэш-роутер остаётся, Pages не требует настройки перенаправлений. Тег `<base href>` не нужен: все пути к ресурсам строятся через `import.meta.env.BASE_URL`.
- Шаг пользователя один раз: в настройках репозитория Pages → Source → GitHub Actions.

## 3. Платформенный адаптер

`src/platform/` с одним интерфейсом и двумя реализациями:

```ts
type Platform = {
  kind: 'telegram' | 'web';
  ready(): void;                                   // Telegram: WebApp.ready() + expand(); web: ничего
  user: { id: string; firstName: string } | null;  // Telegram: initDataUnsafe.user; web: null
  startParam: string | null;                       // Telegram: initDataUnsafe.start_param; web: null
  backButton: { show(onClick: () => void): void; hide(): void };
  haptic(kind: 'light' | 'medium' | 'success' | 'error'): void;
  share(text: string, url: string): Promise<'telegram' | 'native' | 'clipboard' | 'none'>;
  cloud: CloudStorage | null;                       // Telegram: обёртка WebApp.CloudStorage; web: null
};
type CloudStorage = { getItem(key: string): Promise<string | null>; setItem(key: string, value: string): Promise<void>; removeItem(key: string): Promise<void> };
```

- Скрипт `telegram-web-app.js` подключается динамически только когда адрес содержит маркер Telegram (`tgWebAppPlatform` в query или hash); обычный сайт его не грузит. `createPlatform(): Promise<Platform>` ждёт загрузку скрипта не дольше 3 секунд, иначе возвращает web-реализацию.
- Telegram: `share` открывает `https://t.me/share/url?url=…&text=…` через `openTelegramLink`. Web: `navigator.share` если есть, иначе `navigator.clipboard.writeText(text + ' ' + url)` и подсказка «Скопировано».
- Тема всегда наша тёмная; цвета Telegram не читаются. `expand()` вызывается при старте, `enableClosingConfirmation()` во время боя.
- Кнопка «Назад» Telegram показана на всех экранах, кроме меню, и вызывает тот же обработчик, что внутренняя кнопка «Назад»: в свободном бою подтверждение сдачи, в обучении переход в меню, в конструкторе вопрос про несохранённые изменения, иначе переход в меню. Обработчик регистрируется экраном через `ui.setBackHandler(fn | null)` в store; адаптер подписан на него.
- Вибрация: лёгкая на каждом ударе, средняя на смерти, `success`/`error` на результате. Вне Telegram вызовы пустые.

## 4. Ссылки-вызовы

### 4.1. Код вызова

`src/game/links/codec.ts`: `encodeChallenge(c: Challenge): string`, `decodeChallenge(s: string): Challenge | null`.

```ts
type Challenge = { v: 1; deck: Deck; seed: number; name: string };
```

Байтовая раскладка версии 1: `[v=1][6 байт индексов героинь][12 байт индексов карт][4 байта seed, big-endian uint32][1 байт длины имени][имя UTF-8, до 32 байт][1 байт CRC-8]`, затем base64url без `=`. Максимум 57 байт, то есть 76 символов; типично 50. Алфавит base64url совместим с `startapp` Telegram (буквы, цифры, `-`, `_`, лимит 512).

Индексы берутся из замороженных таблиц `CODEC_V1_HEROES` и `CODEC_V1_CARDS` в том же файле: копии порядка `HERO_IDS` и `CARD_IDS` на момент выпуска версии 1. Тест проверяет, что множества совпадают с данными движка; порядок таблиц менять нельзя, новые героини и карты только добавляются в конец. `starting` в коде не хранится: первые три героини колоды стартовые. Имя обрезается до 16 символов и дополнительно до 32 байт UTF-8 (обрезка по целым символам) до кодирования. `decodeChallenge` возвращает `null` при чужой версии, неверной CRC, индексе вне таблицы или колоде, не проходящей `validateDeck`.

### 4.2. Адреса

- Сайт: `https://alessioilini.github.io/eclipse/#/c/<код>`.
- Telegram: `https://t.me/<бот>/<приложение>?startapp=<код>`; при старте `platform.startParam` превращается в переход на `#/c/<код>`.
- Имя бота и приложения в `src/config.ts` (`TG_BOT`, `TG_APP`, `SITE_URL`); пока бот не создан, ссылки для шаринга строятся по адресу сайта. `buildChallengeUrl(code, platform)` выбирает форму по платформе.

### 4.3. Экран вызова

Маршрут `#/c/:code` → экран `Challenge`: заголовок `fmt(ru.challenge.title, { name })`, шесть героинь отправителя (стартовая тройка крупнее, арт в рост), кнопки «Принять вызов» и «В меню». Битый код → `ru.challenge.invalid` и «В меню».

«Принять вызов»: колода игрока это активная колода; если её нет, временная `buildPreset('balanced', HERO_IDS)` без открытия героинь и без сохранения в список колод. Обучение проходить не требуется. Матч стартует через `startMatch(playerDeck, { opponentDeck: challenge.deck, seed: challenge.seed, mode: 'free', challenge: { name, code } })`; `MatchSession` получает необязательное поле `challenge` и оно сохраняется вместе с матчем. Призрак это обычный бот с колодой и seed отправителя, поэтому противник одинаков у всех.

Результат в матче-вызове: заголовок дополняется `fmt(ru.challenge.resultVs, { name })`; «Ещё раз» повторяет тот же вызов с тем же seed; кнопка «Ответный вызов» делает то же, что «Поделиться», с собственной колодой игрока.

## 5. Поделиться

На экране результата любого свободного матча кнопка «Поделиться». Текст: `fmt(ru.share.text, { name, moment, url })`, например: «Алексей выиграл, оставшись с 1 HP. Сможешь победить его команду? <ссылка>». `moment` берётся из `keyMoment`, который начинает возвращать `{ rule, text, heroId?, value? }`; для шаринга используется `text`. Ссылка кодирует колоду игрока из этого матча, новый seed `now() >>> 0` и имя.

Имя: в Telegram `platform.user.firstName`; в браузере при первом шаринге небольшой диалог с полем до 16 символов, значение в `profile.name`. `SaveV1.profile.name?: string` добавляется как необязательное поле без смены версии; `migrate` его не требует.

## 6. Облако Telegram и загрузка

- В Telegram источник истины для `profile`, `decks`, `settings` это облако: три ключа `eclipse.profile`, `eclipse.decks`, `eclipse.settings`, JSON, лимит 4096 байт на значение. Текущий матч остаётся в localStorage. Число колод ограничивается восемью: при восьми «Новая колода» и «Собрать за меня» скрыты с подписью `ru.decks.limit`; это держит `eclipse.decks` в пределах 3 КБ.
- `src/game/save/cloud.ts`: `loadCloud(cloud): Promise<Partial<SaveV1> | null>`, `writeCloud(cloud, save): Promise<void>` с задержкой 1000 мс и слиянием подряд идущих записей; при превышении 4096 запись пропускается с `console.warn` (не бросает).
- Загрузка: `boot(storage, platform)` становится асинхронной. Порядок: `platform.ready()` → локальное сохранение → если есть облако, читаем ключи; найденные ключи заменяют локальные разделы; если облако пустое, локальные разделы записываются в него (перенос прогресса при первом входе) → `hydrate` → `attachPersistence` пишет локально всегда и в облако при наличии. До `hydrate` виден статический каркас из `index.html`, затем меню.
- Если облако недоступно или бросает, игра работает на localStorage и один раз пишет предупреждение в консоль.

## 7. Арт

- `art/style.md`: стиль-библия. Ночное аниме-фэнтези, полуреалистичные пропорции, мягкий рисованный свет луны сверху-слева, тёмный фон в градиенте `--bg` с частицами, акцентный свет цвета стихии на волосах и одежде, без текста и логотипов, без оружия крупным планом. Единая палитра кожи и линий для всех двенадцати.
- `art/prompts.ts`: для каждой героини `{ id, base: string, portrait: string, full: string }`, где `base` описывает внешность и костюм (волосы, глаза, фирменная деталь: Айра угли в волосах, Нериса каменные наплечники и так далее), а `portrait` и `full` добавляют кадр: «портрет по грудь, взгляд в камеру» и «в рост, стоя, лёгкий поворот». Промпты на английском, внизу файла русские заметки для правок.
- `scripts/gen-art.ts` (`npm run art -- [--only aira] [--kind portrait|full]`): читает `OPENAI_API_KEY` из окружения и никогда не печатает; для каждой героини сначала портрет через `POST /v1/images/generations` с моделью `gpt-image-1`, `size 1024x1024`, `quality medium`; затем арт в рост `size 1024x1536` через `POST /v1/images/edits` с портретом как референсом, чтобы лицо и костюм совпали; если ответ сервиса на edits ошибочен, падение назад на обычную генерацию с тем же `base`. Исходные PNG в `art/out/` (в `.gitignore`). Повторный запуск пропускает уже существующие файлы, если нет `--force`. Ориентировочная цена полного прогона около 2 долларов.
- `scripts/art-pack.ts` (`npm run art:pack`): через `sharp` делает `public/art/<id>-portrait-128.webp`, `-portrait-512.webp`, `-full-512.webp`, `-full-1024.webp`; эти WebP коммитятся, суммарно около 1.5 МБ.
- `HeroArt({ heroId, kind: 'portrait' | 'full', size })`: `<img loading="lazy" decoding="async" srcSet>` по соглашению имён, `onError` переключает на инициал в круге; путь строится от `import.meta.env.BASE_URL`. Экраны: бой и сетка героинь используют `portrait`; карточка героини, конструктор колод (слоты) и экран вызова используют `full` с градиентом цвета стихии снизу.

## 8. Изменения в существующих слоях

- `MatchSession.challenge?: { name: string; code: string }` и его сохранение в `SaveV1.match`.
- `SaveV1.profile.name?: string`; `ru.share.*`, `ru.challenge.*`, `ru.decks.limit`, `ru.platform.copied`.
- `keyMoment` возвращает `{ rule, text, heroId?, value? }`; экран результата читает `text`.
- Роутер: маршрут `{ name: 'challenge'; code: string }` ↔ `#/c/<code>`.
- Store: `ui.backHandler`, `ui.setBackHandler`; `boot` асинхронный; `attachPersistence(storage, cloud?)`.
- Меню: кнопка «Вызвать друга» рядом с «Играть» создаёт ссылку с активной колодой (без матча) и открывает шаринг.
- Движок не меняется.

## 10. Тестирование

- Кодек: свойство «кодировать → раскодировать» на 1000 случайных легальных колод с случайными seed и именами (включая кириллицу и эмодзи, обрезка до 16 символов); длина строки ≤ 100; отказ на битой CRC, чужой версии, индексе вне таблицы; таблицы версии 1 совпадают по множеству с `HERO_IDS`/`CARD_IDS`.
- Адреса: сайт и Telegram, обратный разбор `startParam` в маршрут.
- Платформа: подделка `window.Telegram.WebApp` в jsdom: `ready`, `startParam`, кнопка «Назад» зовёт текущий обработчик, `share` зовёт `openTelegramLink` с правильно закодированными параметрами, облако с лимитом 4096 и отказом; web-реализация с `navigator.share` и без него.
- Облако: загрузка заменяет разделы, пустое облако заполняется локальными данными, запись с задержкой и слиянием, превышение лимита не бросает.
- Загрузка: `boot` в Telegram и в web, порядок операций, падение облака.
- Экран вызова: валидный код показывает имя и состав, «Принять вызов» стартует матч с колодой призрака и seed из кода, у двух получателей одинаковый `reveal` в первом раунде; новичок без колоды получает временную; битый код.
- Результат: «Поделиться» и «Ответный вызов» формируют текст и ссылку, раскодируемую обратно в колоду игрока.
- Сквозной тест: открыть `/#/c/<код>` → «Принять вызов» → в бою у противника героини из кода.
- Деплой: workflow проверяется в GitHub Actions на первом push; локально `BASE_PATH=/eclipse/ npm run build` и проверка, что пути ресурсов начинаются с `/eclipse/`.

## 11. Решения, принятые в этой спеке

- Скрипт Telegram грузится только при запуске из Telegram; сайт его не тянет.
- Код вызова хранит индексы по замороженным таблицам версии 1, а не id; порядок таблиц не меняется.
- Призрак это обычный бот с чужой колодой и seed; никакой записи ходов отправителя.
- Получатель без колоды играет временной сбалансированной из всех 12 героинь; обучение не требуется.
- Облако Telegram хранит профиль, колоды и настройки; матч только локально; колод не больше восьми.
- Имя для шаринга из Telegram или из профиля после одного вопроса; в коде вызова имя до 16 символов.
- Арт: две картинки на героиню, портрет служит референсом для арта в рост; исходники не коммитятся, WebP коммитятся.
- Тема только наша тёмная, цвета Telegram игнорируются.
